# Автообновление @nyancash_bot (VPS)

## Что уже обновляется само

- **Nyan Wallet API** размещён на Render (`nyan-wallet-api`), ветка `main`, `autoDeploy: yes`. Для него ничего на VPS перезапускать не требуется.
- **Мини-приложение** находится в этом GitHub-репозитории; публикация GitHub Pages настраивается отдельно от серверного бота.
- **Telegram-бот** запускается на VPS из `/home/nyanteam/new_bot`; для него нужен этот установщик.

## Один запуск в Termius — mjodgiver (cron + nohup)

Telegram-бот запущен через `nohup`, не через systemd. Для этого VPS используйте точно:

```bash
cd /home/nyanteam/nyan-wallet && git pull --ff-only && python3 tools/nyan_bot_autodeploy.py install --service bot.py --scope nohup
```

Установщик сохраняет копию crontab, отключает старые записи `new_bot/keep_bot_alive.sh` (они могли создавать несколько poller-процессов),
устанавливает новую cron-проверку раз в минуту и оставляет ровно один процесс `new_bot/bot.py`.

Первое включение НЕ переписывает текущие модули (чтобы не стереть локальные исправления);
последующие изменения модулей из GitHub автоматически синхронизируются и приводят к перезапуску.

Для других серверов systemd по-прежнему поддерживается через `--scope user` или `--scope system`.
## Поведение при обновлении

1. Раз в минуту сравнивает состояние `origin/main` и последнюю успешно применённую версию.
2. Проверяет синтаксис Python в кандидатном Git worktree **до** применения.
3. Не меняет `.env`, базу данных, `bot.py`, сохранённые состояния/покупки.
4. Копирует только ранее установленные модули `bot_addons/*.py`, **изменившиеся с прошлого успешного деплоя**. Архив розыгрышей обновляет через адаптер при изменении в GitHub.
5. Сохраняет исходные файлы в `~/.local/state/nyan-bot-autodeploy/backups/`.
6. Перезапускает бот через systemd либо nohup в зависимости от режима. Для nohup также устраняет отсутствие процесса или несколько параллельных процессов.
7. Если запуск неудачен, восстанавливает модули и старый Git-коммит. Проблемную версию блокирует до следующего коммита либо ручной команды `retry`.

**Ограничение:** основной `bot.py` по-прежнему живёт на VPS и не синхронизируется из GitHub. Новые модули, которых раньше не было в `new_bot`, автоматически не регистрируются в `bot.py`. Автодеплой синхронизирует существующие обработчики; их программные ошибки (например, некорректный формат кнопок Telegram) синтаксическая проверка не обнаружит.

## Проверка

```bash
cd /home/nyanteam/nyan-wallet
python3 tools/nyan_bot_autodeploy.py status
tail -n 60 ~/.local/state/nyan-bot-autodeploy/deploy.log
crontab -l | grep NYAN_BOT_AUTO_DEPLOY
```

В случае ошибки после исправления кода и нового коммита автодеплой попробует снова. Для повторной попытки того же коммита:

```bash
python3 tools/nyan_bot_autodeploy.py retry
```

Выключить автообновление (не останавливает бот):

```bash
(crontab -l | grep -v NYAN_BOT_AUTO_DEPLOY) | crontab -
```

**Примечание.** Обновление на Render и GitHub Pages происходит по их собственным настройкам. Скрипт VPS не отвечает за задержки их публикации или кеш Telegram WebView.
