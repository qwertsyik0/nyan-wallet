# Nyan Elections — архитектура и первый этап (16.10.2026)

## Согласованная схема

- **Nyan Shop:** новости, публикации программ, агитация, дебаты и официальные объявления. Не хранит бюллетени и не считает голоса.
- **Nyan Wallet:** создание и одобрение партий, список членов, отдельная страница «Выборы», избирательный реестр, тайное голосование, результаты.
- **Партия:** уникальные в сезоне название и сокращение, программа, эмблема (HTTPS), председатель, статус заявки.
- **Участие:** один человек может состоять не более чем в одной партии данного сезона; участник вправе сменить партию только до голосования; председатель не меняет партию, пока не реализована передача полномочий.
- **Голос:** один допущенный Telegram-пользователь — один голос; голосовать можно за любую зарегистрированную партию; результаты открываются после закрытия голосования.
- **Антифрод:** существующий список заблокированных пользователей учитывается уже на этапе создания/вступления. До реального голосования необходима отдельная процедура допуска и проверки подозрительных мультиаккаунтов. Оценка риска сама по себе не является доказательством.
- **Цикл:** подготовка/регистрация партий → одобрение → набор → агитация/дебаты → голосование → результаты/коалиции → 7 дней правления → следующий сезон. Полный цикл ориентировочно 7–10 дней, но точные даты устанавливает владелец.
- **Коалиции:** при отсутствии результата более 50% предусмотрены переговоры; автоматическое создание коалиции в первой версии не реализуется.

## Реализовано в ветке

Модуль `server/elections.py` содержит модели `ElectionSeason`, `ElectionParty`, `ElectionMembership`, уникальные ограничения базы данных и следующие методы:

| API | Доступ | Назначение |
| --- | --- | --- |
| `GET /api/elections` | подтверждённый Telegram | Текущий сезон, одобренные партии, своё членство, собственные заявки |
| `POST /api/elections/owner/seasons` | только владелец | Создать первый/следующий сезон, если предыдущий закрыт |
| `POST /api/elections/parties` | пользователь кошелька | Подать одну заявку на партию во время регистрации |
| `GET /api/elections/owner/pending` | только владелец | Список партий, ожидающих решения |
| `POST /api/elections/owner/parties/{id}/review` | только владелец | Одобрить/отклонить ровно один раз |
| `POST /api/elections/owner/phase` | только владелец | Перейти последовательно registration → recruitment → campaign |
| `POST /api/elections/parties/{id}/join` | пользователь кошелька | Вступить или сменить партию до голосования |
| `POST /api/elections/parties/leave` | участник | Покинуть партию до голосования |

Все мутации используют Telegram `initData` и транзакции SQLAlchemy. БД ограничивает членство единственной партией в рамках сезона. Заявки `pending` недоступны другим пользователям до решения владельца. Никакие операции с балансами/Stars/лапкоинами не добавлены.

## Кнопка «🗳 Выборы» для рассылок и каналов

Готова в исходниках, **не опубликована в работающем боте** до внедрения всего этапа и обновления бота на VPS.

- В `/broadcast` появилась готовая кнопка `🗳 Выборы` в редакторе исходного сообщения. Она создаёт `InlineKeyboardButton(web_app=.../elections.html)` для личных чатов; дедупликация предотвращает двойное добавление.
- В `/channel_post` (обе версии `channel_publish_bot.py` и `channel_publish_bot_v2.py`) появилась такая же быстрая кнопка. В Telegram-канал бот публикует обычную URL-кнопку `https://t.me/<bot_username>?startapp=elections`, а не недопустимый для каналов `web_app`.
- `index.html` перенаправляет `startapp=elections` на `elections.html` с сохранением Telegram launch context; страница использует подписанный `X-Telegram-Init-Data` и показывает список партий, регистрационные формы и панели владельца.
- Рассылка/публикация **не запускается автоматически**: кнопка лишь добавляется в черновик, затем нужен обычный предпросмотр и подтверждение отправки.
- Тест `tools/test_elections_buttons.py` проверяет соответствие маршрутов для разных конструкторов и целевой страницы.

## НЕ реализовано и не открыто

- В действующем Mini App ещё не опубликована новая страница, а внутренняя вкладка навигации Nyan Wallet не добавлена (отдельная страница `elections.html` уже создана в ветке).
- Публикация агитационных постов и интеграция с информационным каналом Nyan Shop.
- Готовый реестр избирателей и решение спорных антифрод-случаев.
- Тайные бюллетени, атомарная защита от повтора, закрытие урн, результат только после закрытия, аудит.
- Коалиционные переговоры, полномочия победителя и автоматическое окончание 7-дневного срока.
- Закрытие сезона и переход к следующему.

Сервис намеренно **не разрешает** `voting` и не имеет `/vote` или `/results` до выполнения этих условий.

## Проверка

`python tools/test_elections_foundation.py` поднимает тестовый FastAPI и SQLite со **специально подменённой тестовой** Telegram-авторизацией, без боевых токенов и подключения к PostgreSQL. Проверяет права владельца, обязательную авторизацию, уникальные партии, модерацию, невозможность повторного решения, членство, смену партии и блокировку недопустимых переходов.

GitHub Actions: https://github.com/qwertsyik0/nyan-wallet/actions/runs/38957188528 — `success` (backend и Telegram-кнопки).

**Раскатка:** ни один файл не переносился в `main`, Render не перезапускался. Этап проверен тестами, но ещё не проверен на живой Telegram WebApp или настоящей PostgreSQL. Публикация и открытие выборов требуют отдельной проверки и завершения недостающих этапов.
