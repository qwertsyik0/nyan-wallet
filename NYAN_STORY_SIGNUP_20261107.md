# NYAN GAMES — запись на сюжетную игру

Это только страница записи, не игровая площадка. Участник видит свой
подтверждённый Telegram `@username` и кнопку «записаться».

## Сценарий

1. Владелец отправляет `/story` в нужной группе Telegram, где уже состоит бот.
2. Бот вызывает серверный API по подписанному запросу. Сервер открывает новый
   набор и ставит сообщение с кнопкой в существующую очередь Telegram relay.
3. Кнопка `https://t.me/nyancash_bot?startapp=nyan_story` открывает
   `nyan-story.html` внутри Nyan Wallet Mini App.
4. Нажатие «записаться» проверяет Telegram `initData`, сохраняет Telegram ID
   и `@username` в PostgreSQL и в той же транзакции ставит **одно** уведомление
   владельцу. Повторное нажатие не добавляет дубликат.
5. `/story_close` от владельца в той же группе закрывает набор.

Оба обработчика команд игнорируют остальных пользователей. Адрес целевой группы
определяется по чату, из которого владелец вызвал команду. Сервер проверяет
подпись, срок и идентификатор чата; токен бота не попадает на клиентскую страницу.

## Где что находится

- `nyan-story.html`, `nyan-story.css`, `nyan-story.js` — страница регистрации;
- `assets/nyan-story/horror-corridor.webp` — пиксельный хоррор-фон;
- `index.html` — маршрутизация `startapp=nyan_story`;
- `server/nyan_story_signup.py` — API, таблицы и уведомления;
- `server/__init__.py` — регистрация модуля при старте FastAPI;
- `bot_addons/nyan_story_bot.py` — команды `/story`, `/story_close`;
- `tools/install_nyan_story_bot.py` — безопасное подключение команд к боту.

## Подключение на существующих хостах

В репозитории не хранятся секреты. Используются имеющиеся переменные:
`BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `NYAN_TELEGRAM_RELAY_SECRET` на сервере.
На хосте бота нужен рабочий HTTPS-адрес API через `NYAN_STORY_API_URL`
или уже существующую `NYAN_WALLET_API`/`NYAN_WALLET_API_URL`.

На FirstVDS рабочая папка `/opt/nyan-wallet` содержит ручные изменения. **Не делать
`git pull` поверх неё.** Для установки только API регистрации предусмотрен
отдельный установщик с предварительной проверкой, резервной копией и откатом:

```bash
curl -fsSLo /tmp/install_nyan_story_firstvds.py https://raw.githubusercontent.com/qwertsyik0/nyan-wallet/feat/nyan-story-signup-20261107/tools/install_nyan_story_firstvds.py
sudo python3 /tmp/install_nyan_story_firstvds.py --check
sudo python3 /tmp/install_nyan_story_firstvds.py --apply
```

При успешной установке проверяются четыре маршрута API. Новый модуль при
старте создаёт только две собственные таблицы `nyan_story_rounds` и
`nyan_story_signups`; он не открывает запись и не рассылает сообщения.

На **отдельном** хосте Telegram-бота (не FirstVDS API) из обновлённого
репозитория, после объединения PR:

```bash
python3 tools/install_nyan_story_bot.py --root /home/nyanteam/new_bot --check
python3 tools/install_nyan_story_bot.py --root /home/nyanteam/new_bot --apply
```

Установщик делает резервные копии изменённых файлов и проверяет синтаксис.
Он **не перезапускает** бота и ничего не отправляет. После проверки нужно
перезапустить уже используемый процесс бота штатным способом, не запуская
вторую параллельную копию.

GitHub Pages должен обновить статические файлы с основной ветки отдельно.
До обновления сайта и обоих серверных компонентов команду `/story` не запускать.

## Проверка после установки

1. Владелец отправляет `/story` в тестовой группе, где бот может публиковать.
2. Появляется одно сообщение с кнопкой «записаться в игру».
3. Тестовый пользователь с Telegram username открывает кнопку и записывается.
4. В PostgreSQL появляется одна запись, владельцу приходит одно уведомление.
5. Повторная запись показывает подтверждение и не дублирует уведомление.
6. Владелец отправляет `/story_close`, после чего запись недоступна.

Примечание: разработка и синтаксические проверки локальные. Живое Telegram
уведомление и сервисный деплой требуют проверки после установки на хостах.
